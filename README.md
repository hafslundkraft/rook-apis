# rook-apis

Parts of [Rook](https://rook.io)'s `ceph.rook.io/v1` Go API types, without Rook's dependency tree.

## Why this exists

Rook publishes its API types as the Go module `github.com/rook/rook/pkg/apis`. Importing them directly from there, is a lot of hassle.

- upstream Rook uses `replace` and `exclude` directives in their `go.mod` ([rook/rook#13304](https://github.com/rook/rook/issues/13304)). Those are not inherited if we import the module. We would need to copy them into our own `go.mod` to make it work.
- The module has no release tags, only pseudo-versions.
- Rook ships no apply configurations, so there is no typed server-side apply.

This module holds verbatim copies of the Rook types we use, as well as deepcopy functions and apply configurations generated by controller-gen.

```go
import (
	cephv1 "github.com/hafslundkraft/rook-apis/ceph.rook.io/v1"
	cephv1ac "github.com/hafslundkraft/rook-apis/applyconfiguration/ceph.rook.io/v1"
)
```

## Versioning

A tag is the Rook release the types come from, followed by a counter: `v1.21.0-1`, `v1.21.0-2`.
Everything before the dash, is the upstream rook version. Everything after the dash, is our subversion of rook's upstream version. A workflow tags every merge to main: the Rook version comes from `ROOK_VERSION`, and the subversion is one higher than the last tag for that version. Don't create tags by hand: a plain tag such as `v1.21.0` would outrank every subversion tag.

## Updating

Set `ROOK_VERSION` to the new Rook release, copy the same declarations from that release into `ceph.rook.io/v1/types.go`, and run `make generate check-upstream`. The check compares every type in `types.go` byte for byte with the type of the same name in Rook at `ROOK_VERSION`, and CI runs it too. The merge to main is automatically tagged with an appropriate version increment.
